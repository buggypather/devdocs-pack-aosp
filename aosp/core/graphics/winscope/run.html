Run Winscope

Winscope tracing is part of the Android framework. This page outlines the steps required to download, build, and run the Winscope trace viewer locally.

Build Winscope locally

Follow these steps to set up your PC to run the Winscope tracer:

  1. Download the Android source.

  2. Navigate to the Winscope folder:

    cd development/tools/winscope

  3. Install dependencies using:

    npm install

    To see a list of available commands, run: npm run

  4. Build all prod and test targets using:

    npm run build:prod

  5. Run Winscope using:

    npm run start
Note: You can also download and build Winscope to host on a standard web server to get a shareable link to the tool.

Build separate parts

You can build individual parts of Winscope separately using the following commands:

Command Description
build:trace_processor Checks out and rebuilds the latest version of
Perfetto's trace_processor.
build:protos Recompiles the proto definitions.

Run tests

Tip: Winscope doesn't build on Soong and can't be built by Tradefed, so it's recommended to have a local Git hook to the tests in your local environment.

Winscope contains unit and end-to-end tests. To run them use npm run <command>:

Command Description
test:unit:ci Runs the unit tests in a less verbose format for CI
or presubmit hook.
test:unit:dev Runs the unit tests in a more verbose format for
local development. This mode watches for changes and
automatically reruns the correct tests.
test:e2e Runs the end-to-end tests, such as those for the
cross-tool protocol.
test:presubmit:quiet Builds all presubmit unit tests, linters, and graph
analysis in a less verbose format for CI or presubmit
hook.
test:presubmit Builds all presubmit unit tests, linters, and graph
analysis in a more verbose format for local
development.
test:all Runs all tests (unit and end-to-end), linters, and
graph analysis in a more verbose format for local
development.

End-to-end tests

Before running end-to-end tests, you must start the remote tool and install the correct version of the Chrome driver. In the following code snippet, the run test:e2e command automatically installs the Chrome driver.

$ npm run start
$ npm run start:remote_tool_mock
$ npm run test:e2e

The following table lists the necessary commands and their descriptions. To run them use npm run command:

Command Description
start:remote_tool_mock Starts the remote tool mock for testing cross tool protocol.
install:chromedriver Installs the Chrome driver necessary to run end-to-end tests.

Update @IntDef mapping

@IntDef is an annotation used in Android to restrict the possible values of an integer. Winscope uses a mapping of these annotations to display the name of the value instead of the integer.

If new @IntDef values are added to the Android framework but not updated in Winscope, they are displayed as raw integer values instead of descriptive strings. To fix this issue, update the IntDef mapping file (development/tools/winscope/src/common/intDefMapping.json).

To automatically update the @IntDef mapping, do the following:

  1. Run the update_intdef_mappings.sh script from the development/tools/winscope/scripts/ directory in your local Android tree. This script triggers the annotation process that extracts the latest @IntDef values from the code and updates intDefMapping.json:

    cd development/tools/winscope
./scripts/update_intdef_mappings.sh

  2. Commit the changes to src/common/intDefMapping.json using the git commit command and upload them using the repo upload command.

If the script isn't available, follow these steps to update the @IntDef mapping manually from your Android root directory ($ANDROID_BUILD_TOP):

  1. Build framework-minus-apex-intdefs for the annotation preprocessor to run:

    m framework-minus-apex-intdefs

  2. Copy the generated intDefMapping.json file to the prebuilts repository:

    $ python3 -c 'import sys,json,collections; print(json.dumps(collections.OrderedDict(sorted(collections.ChainMap(*map(lambda x:json.load(open(x)), sys.argv[1:])).items())), indent=2))' $(find out/soong/.intermediates/frameworks/base -iname intDefMapping.json) > ./development/tools/winscope/src/common/intDefMapping.json

  3. Upload the changes in Winscope using repo upload.

Troubleshoot

Use the following tips for troubleshooting:

  • Error ProtocolError: missing required '<FIELD>' or TypeError: Cannot read property '<PROP>' of null

    • This occurs when the trace file was created with a new proto definition, containing new required fields.

      1. Make sure you're opening the trace on the correct Winscope version (master, S, or R).

      2. If you create the new field on the proto, recompile the protos in Winscope using npm run build:protos.

        Note: You shouldn't need a new required field, because the protos should be backward compatible.

  • Some installed dependency versions are wrong (build fails)

    • Revert changes to package.json and package-lock.json. Remove node_modules. Run npm install again.

  • I added a new field to one of the proto files. How do I display it?

    • Winscope uses the proto definitions from when it was compiled, so new fields won't appear by default. To show new fields, rebuild the protos using npm run build:protos.
