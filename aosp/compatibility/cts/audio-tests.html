CTS Verifier audio tests

This page covers the general instructions, required test equipment, and test suite mapping for running the audio tests in CTS Verifier (CTS-V).

General instructions

The following procedures apply to all tests:

  • Test setup: For each test, you need a device under test (DUT), which is the Android-powered device you're testing, and an installed version of CTS-V associated with the Android OS version running on the DUT. For more general information about CTS-V requirements and setup, see Using CTS Verifier.

  • Test information: To run an audio CTS-V test, launch the CTS-V app, and then select the preferred test from the CTS Verifier test list. Opening a test for the first time displays the info panel for that test, which contains the following information:

    • Test purpose
    • Test protocol
    • Required peripherals
    • Reference to the relevant CDD section

    To close the info panel, tap OK. To view the info panel at any time during testing, tap the ? button.

  • Test runs: Use the test-specific instructions in this section to run each audio test.

    • When the test passes, the checkmark Pass button is enabled. Record a passed test by tapping this button. Some tests also display the message PASS near the bottom row of buttons.
    • Record failed tests by tapping the X button.
    Note: For tests that have multiple APIs available, you're required to test only one API. We recommend testing the Native API.

  • Optional and feature-gated tests: When a DUT doesn't declare a required hardware port or system feature for a test (or specific test route), CTS-V displays a "Skippable or Non-Mandatory" message (or skips the unsupported route) and automatically enables the Pass button.

Many CTS-V audio tests are self-contained and provide full instructions directly in the app (tap the ? button). The guides in this section cover tests that require external hardware setups, calibration panels, or peripheral configurations.

Test equipment and common panels

CTS-V audio tests use the following test equipment and shared configuration panels:

  • Standalone DUT (built-in speaker and microphone): Uses the device's internal speakers and microphones in a quiet environment (no external hardware required).
  • 3.5 mm analog headset: Standard wired 4-conductor, 3.5 mm headset with a microphone and inline media buttons (used for headset plug and key-code detection).
  • Audio loopback plug: A 3.5 mm TRRS loopback plug that routes headphone output directly back to the microphone input.
  • USB-to-analog headset adapter: Converts a USB digital audio signal to a standard 3.5 mm analog jack (used with a 3.5 mm analog headset or audio loopback plug).
  • USB audio interface: An external multi-channel USB audio interface connected with 1/4-inch patch cables (for loopback) and a USB OTG adapter.
  • Multichannel USB audio peripherals: A 4-in/4-out USB audio interface (such as Zoom AMS-44 or Focusrite Scarlett 4i4) with Y-splitter or 1/4-inch patch cables for 4-channel input testing, and a 7.1-channel USB audio adapter (such as Vantec NBA-200U) with a 6-way stereo audio mixer (or 4-channel audio switcher) and 3.5 mm breakout cables for 8-channel output testing.
  • MIDI peripherals: A USB MIDI peripheral (with standard 5-pin DIN MIDI loopback cable), a Bluetooth LE (BLE) MIDI device, or a virtual MIDI synth app.
  • Auxiliary device: A second calibrated Android-powered device capable of playing and recording near-ultrasound frequencies.
  • Head-tracking device: A spatial audio head-tracking headset or motion test rig.
  • Shared CTS-V UI panels:
    • Audio loopback calibration panel: Used across standalone, 3.5 mm analog, and USB loopback tests to calibrate output and input signal levels before running a test.
    • Audio devices panel: Displays connected audio input and output peripherals to verify device discovery and routing capabilities.
