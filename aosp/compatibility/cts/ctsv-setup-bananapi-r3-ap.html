Set up the BananaPi-R3 access point

This pages describes the setup process for the BananaPi-R3 access point (AP) BPi-R3, which is used in Wi-Fi AP connection testing for Android 16 QPR2 and higher.

Purchase a BananaPi-R3 access point

To purchase a BananaPi-R3 access point:

  1. Purchase the Banana Pi R3 AP and accessories listed in this table:

    Item Quantity
    BPi-R3 board, similar to the Banana Pi BPI-R3 Router Board with MediaTek MT7986 chip design support Wi-Fi 6 ,2G DDR RAM ,8G eMMC flash onboard 1
    BPi-R3 aluminum case, similar to the BPI-R3 Iron case 1
    BPi-R3 aluminum heatsink (cooling fan), similar to the BPI-R3 aluminum heatsink with fan 1
    2 and 5 GHz antenna with cable, similar to the 5DB antenna in the BPI shop 8
    Power adapter, similar to the 12V/2A DC power supply 1

  2. To finalize your purchase, see the Easy to buy section of the Banana Pi BPI-R3 page.

    2. Mount the fan and secure it with four screws from the underside of the RPi-R3 board. Figure 2 shows the location of fan mounting holes on the underside of the BPi-R3 board:

    3. Connect the fan to the power source at the location labeled FAN. Figure 3 shows the fan power connector on the BPi-R3 board:

  2. Screw the BPi-R3 board onto the case at the four corners. Figure 4 shows the location for the four corner screws in the case:

Flash OpenWrt image

Flashing the device is a two-stage process:

  1. Load the OpenWrt image onto an SD card.
  2. Flash the OpenWrt image from the SD card to the AP's on-device storage.
Note: The SD card is reusable and you can use it to set up all your BPi-R3 APs.

Load the OpenWrt image onto an SD card

This section explains how to load the OpenWrt image onto an SD card.

Prerequisites

To load the OpenWrt image onto an SD card, you need:

  • An internet-accessible subnet.
  • A Linux computer on this subnet. Use this computer to prepare the SD card and to connect to AP using SSH.
Note: If you already have an SD card with the correct version of the OpenWrt image, skip this section and re-use that SD card for flashing all BPi-R3 APs.

Load OpenWrt image onto an SD card

To flash the OpenWrt image to an SD card, do the following:

  1. Download the OpenWrt image.
  2. Plug your SD card in to the Linux machine.

  3. Wipe all existing partition tables and file system identifiers with this command:

    sudo wipefs -a /dev/sd#
    Note: The commands in this section use /dev/sd# as the SD card dev path. Replace this path with path to the SD card device on your machine.

  4. Burn the SD card:

    sudo dd if=openwrt-23.05.5-cros-1.4.0-standard-1.0.2-mediatek-filogic-bananapi_bpi-r3-sdcard.img of=/dev/sd# bs=1000M && sync && sync && sync

  5. Wait for 3 seconds and unplug the SD card.

  6. Verify that all the bootstrap jumpers of the AP are set to high. This jumper setting is required to boot the AP from the SD card. Figure 10 shows the location of the bootstrap jumpers.

    Figure 10. Location of bootstrap jumpers.

  7. Verify that an Ethernet cable is connected to the WAN port of the AP.

  8. Insert the SD card in to the AP.

  9. Connect the power cable to the AP. A second LED indicator flashes green; wait until it stops flashing. Figure 11 shows the LED indicators:

    Figure 11. LED indicators.

Note: The commands in this section use /dev/sd# as the SD card dev path. Replace this path with path to the SD card device on your machine.

Verify the SD card image version

After you have loaded the OpenWrt image onto an SD card, verify the version of the image by doing the following:

  1. Identify the IP address for the AP. To identify the IP address, see Appendix A: Find the IP address of the AP.

  2. Download the SSH identity testing_rsa file to a Linux computer on the same subnet as the AP.

  3. Grant the required permissions:

    chmod 600 path-to-testing_rsa-file

  4. Use SSH to connect to the AP from the host computer:

    ssh -i path-to-testing_rsa-file root@IP

    A screen similar to the following appears:

    Figure 12. Use SSH to connect to the AP.

  5. Verify that the version number on the AP matches the version number highlighted on Figure 12.

Flash OpenWrt image from SD card to BPi-R3 AP

Due to hardware design, flashing the OpenWrt image from SD card to the AP's eMMC is a two-stage process:

  1. Flash image from SD card to NAND storage.
  2. Flash OpenWrt from NAND to eMMC.

Flash image from SD card to NAND storage

To flash the OpenWrt image from the SD card to NAND storage:

  1. Insert the SD card in to the AP.

  2. Power on the AP and wait until boot completes. Verify that the second LED indicator marked G shows a steady green light. Figure 13 shows the LED indicators:

    Figure 13. LED indicators.

  3. Sign in to the AP using SSH.

  4. Run the following command to configure the next reboot to install image from SD card to the NAND flash:

    fw_setenv bootcmd "env default bootcmd ; saveenv ; run ubi_init ; bootmenu 0"

    This command configures the next reboot to install image from SD card to the NAND flash.

  5. Reboot the AP:

    reboot

  6. Wait until boot completes by verifying that the second LED indicator shows a steady green light.

  7. Verify that you can sign in to the AP using SSH.

    Note: The green light status changes during the startup process. After the green light first turns on, the light is steady for several seconds, then it begins to flash, and then becomes steady and no longer flashes.

  8. Unplug the AP's power cable.

  9. Set the bootstrap jumpers to boot from NAND. Figure 14 shows the new boot stramp jumper settings:

    Figure 14. New bootstrap jumper settings.

  10. Power on the AP and wait until the AP boot completes.

  11. Identify the IP address for the AP. To identify the IP address, see Appendix A: Find the IP address of the AP.

  12. Sign in to the AP with the new IP address.

  13. Run the following command to verify you're running an OpenWrt system installed on NAND:

    df -h

    The output should show a disk file system with /dev/ubi0_6. Figure 15 shows the output:

    Figure 15. Output of df -h command.

Flash OpenWrt from NAND to eMMC

To flash OpenWrt from NAND to eMMC:

  1. In the SSH session, run the following command:

    fw_setenv bootcmd "env default bootcmd ; saveenv ; saveenv ; run emmc_init ; bootmenu 0"

    This command configures the next reboot to install image from NAND to eMMC.

  2. Reboot the AP:

    reboot

  3. Wait until boot completes by verifying that the second LED indicator shows a steady green light.

  4. Unplug the AP's power cable.

  5. Unplug the SD card from the AP.

    Note: After the initial setup is complete, the BPi-R3 AP doesn't need the SD card. You can reuse this SD card for setting up other BPi-R3 APs.

  6. Set the bootstrap jumpers to boot from eMMC. Figure 16 shows the new boot stramp jumper settings:

    Figure 16. New bootstrap jumper settings.

  7. Power on the AP and wait until the AP boot completes.

  8. Identify the IP address for the AP. To identify the IP address, see Appendix: Find the IP address of the AP.

  9. Sign in to the AP using the new IP address.

  10. Run the following command to verify you're running an OpenWrt system installed on NAND:

    df -h

    The output should show a disk file system with /dev/fitrw. Figure 17 shows the output:

    Figure 17. Output of df -h command.

  11. Run the following command:

    cat /sys/block/mmcblk0/device/type

    The output should show MMC instead of SD.

The AP setup process is complete.

      ether f8:63:3f:2e:63:e6  txqueuelen 1000  (Ethernet)
      RX packets 0  bytes 0 (0.0 B)
      RX errors 0  dropped 0  overruns 0  frame 0
      TX packets 0  bytes 0 (0.0 B)
      TX errors 0  dropped 0 overruns 0  carrier 0  collisions

  2. Identify the IP address of the AP. The IP address is the value of the inet field of the eno1 interface (100.103.191.133).

  3. Identify the netmask of the eno1 interface (255.255.255.0).

  4. Use the following table to obtain the network prefix length from the netmask:

    Netmask Network prefix length
    255.255.255.252 30
    255.255.255.248 29
    255.255.255.240 28
    255.255.255.0 24
    255.255.252.0 22
    255.255.248.0 21
    255.255.0.0 16
    Note: The network prefix length is the number of leading 1 bits in the netmask binary representation. For example, 255.255.255.252 in binary is 11111111.11111111.11111111.11111100 or 30 leading 1 bits.

  5. Disconnect the AP from the host's LAN interface.

  6. Run the following command to obtain the host LAN IP addresses of devices connected to the host:

    sudo nmap -sP IP/network-prefix-length
    Note: Because the AP is disconnected from the host, this command doesn't list the AP's IP address.

  7. Connect the AP to the host.

  8. Perform step 6 again. A new IP address, the IP address of the AP, appears.
